Construct — Phase 1 Backlog

A modular, independent, parallelizable roadmap for building the architecture framework in small, testable units before composing them into a single product.

Epic 1 — Foundation & Runtime Bootstrapping

Establish the minimal runtime, command surface, and execution model so all other modules can be developed independently and assembled later.

CLI command registration and dispatch

C-01
Core

Implement a thin command registry that routes init, validate, sync, doctor, feature, and generate calls.

  • Clean argument parsing
  • Meaningful help output
  • Stable exit codes

Project root and environment detection

C-02
Core

Detect the current project directory and derive the runtime context for config loading and validation.

  • Resolve absolute root path
  • Support nested project contexts
  • Expose project metadata as a simple object

Doctor command and environment health checks

C-03
Validation

Report local environment readiness and config presence in a developer-friendly format.

  • Node and npm checks
  • Architecture config health
  • Actionable diagnostics

Epic 2 — Configuration & Policy System

Build the explicit policy layer that defines architecture defaults, rule severities, and project overrides without tying the logic to CLI behavior.

Default rule registry

P-01
Config

Create the canonical registry of default rules and metadata for each rule ID.

  • Rule name
  • Default severity
  • Owner and rationale

Architecture config loader

P-02
Config

Load and normalize architecture.yml, merging defaults with project overrides.

  • YAML parsing
  • Default fallback
  • Override validation

Rule severity and exception model

P-03
Policy

Support error, warning, and off severities as well as temporary exception scoping.

  • Rule override resolution
  • Scoped path exceptions
  • Expiration handling

Epic 3 — Project Discovery & Layer Mapping

Discover files, ignore generated directories, and map code to layer ownership so validators can reason over real project structure.

File walker and ignore rules

D-01
Discovery

Scan the project tree and ignore folders that are not architecture-relevant.

  • Ignore node_modules, .next, .git
  • Collect source files
  • Normalize paths

Feature root detection

D-02
Discovery

Identify where feature slices live and create a stable project model for validation.

  • Resolve features root
  • Recognize feature names
  • Map related files to a feature

Layer detection from file path

D-03
Discovery

Determine the architectural layer for each file using the repo structure and naming conventions.

  • route, controller, page, component, workflow, service, domain
  • Stable layer mapping API
  • Support custom layer conventions later

Epic 4 — Validation Engine & Rule Execution

Turn the architecture policy into executable checks with a modular rule engine that can be extended without rewriting the validator core.

Rule engine core

V-01
Validation

Provide the central engine that runs rules against files and collects violations.

  • Rule execution loop
  • Severity evaluation
  • Violation result structure

Route and page boundary rules

V-02
Rules

Enforce route delegation and page presentation constraints.

  • No page workflow imports
  • No page service imports
  • No page domain imports
  • No fetch in page

Component and workflow boundary rules

V-03
Rules

Block application logic from presentation-only layers.

  • Component cannot import controller/workflow/service/domain
  • Workflow cannot import React/UI
  • Service cannot import React/UI

Feature isolation and public API rules

V-04
Rules

Enforce feature boundaries and public API usage across slices.

  • No internal feature imports
  • Require feature index.ts public access
  • Flag architecture leaks

Domain purity and side effect rules

V-05
Rules

Protect pure domain logic from I/O and UI concerns.

  • No fetch in domain
  • No browser globals
  • Service owns external effects

Epic 5 — Generation & Scaffolding

Create a modular generator framework that can generate features and layers while preserving the default architecture contract.

Feature generator

G-01
Generator

Create a feature directory scaffold with required layer folders and API entry points.

  • controllers, workflows, pages, services
  • types.ts and index.ts
  • consistent naming and layout

Layer generator registry

G-02
Generator

Support generating individual architecture layers from a registry of templates.

  • Page, component, workflow, service, domain, controller
  • Template selection by layer
  • Naming normalization

Template rendering and file writing

G-03
Generator

Render generated files and write them safely with consistent output conventions.

  • Template engine abstraction
  • Safe directory creation
  • Deterministic file output

Make validation understandable to humans and reliable for automation, IDEs, and CI systems.

Violation object model

R-01
Reporting

  • Rule ID

Human-readable console formatter

R-02
Reporting

Format violations so devs can quickly understand what is wrong and where it is.

  • Readable summaries

  • Readable warning vs error output

JSON output for automation

R-03
CI

Provide a stable machine-readable output mode for CI, editors, and downstream tools.

  • JSON contract
  • Consistent schema
  • CI-friendly exit codes

Epic 7 — Quality, Testing & Integration

Ensure every module is independently testable and that the whole framework composes cleanly when assembled.

Fixture-driven unit tests

Q-01
Tests

Create reusable fixtures for valid and invalid architecture scenarios.

  • Valid project fixture
  • Invalid page fixture
  • Invalid feature boundary fixture

Module-level test coverage

Q-02
Tests

Each module owns its own tests to keep independent development safe and parallel.

  • Config tests
  • Discovery tests
  • Rule tests
  • Generator tests

End-to-end validation flow

Q-03
Integration

Assemble the full stack and validate that command execution works as a single product.

  • init → config → validate
  • generate → validate
  • reporting and pass/fail status

Epic 8 — Combination / Product Integration

This is the final integration epic that stitches the independent modules together into one working framework and proves the system works as a whole.

Compose the framework runtime

I-01
Integration

Wire together config, discovery, validation, reporting, and CLI into a single runtime pipeline.

  • Stable API assembly
  • Shared contracts between modules
  • Minimal cross-module coupling

Construct init happy path

I-02
Integration

Verify that a fresh project can be initialized and validated with the default architecture policy.

  • architecture.yml created
  • AGENTS.md created
  • feature root generated
  • initial validation passes

Generated feature validation

I-03
Integration

Ensure generated features pass validation immediately after creation.

  • Generated templates follow architecture rules
  • Validation passes without extra edits
  • Violations are actionable when invalid

Release readiness and package validation

I-04
Release

Run the package through the end-to-end quality gate before declaring Phase 1 complete.

  • Tests pass
  • CLI works from package entry
  • Validation output is stable
  • Docs align with behavior
