### R1.1 — 2026-09-27

- note: R1.1 is a minor release of hardening and one layout fix. No pipeline result, generated file or eval number changes (the 11 examples' golden output is byte-identical; `npm run eval:gate` passes).
- feat: endpoints with more than one path parameter, or one that is not last (`/a/{id}/b/{sub}` becomes `/a/:id/b/:sub`), are now imported and listed like any other endpoint instead of being reported as gaps. The generator still calls one trailing `:param`, so they are marked `wired: false` ("not generated" in the Contract card) and are never picked as the list, create, update or remove endpoint; `src/endpoint-paths.mjs` is the one place that decides item versus list (the matcher and the contract reader used to each carry a copy). A file with only such endpoints is still refused as a contract.
- fix: the carry of uploaded contracts into a rolled-back or redeployed build (`carryUserContracts`) is atomic: each file is copied to a temp name, checked byte for byte and renamed over the target, and the example's other `openapi.*` are removed only afterwards. It used to remove first, so a failure in between could leave the older build without a contract.
- fix: an upload that arrived between the carry and the server stop was lost. A deploy or rollback now holds `deploy/contracts.lock`; while it exists the running server answers `POST /api/openapi` and `POST /api/demo/apply-fix` with `503` and `Retry-After` (a stale or expired lock is ignored), and the contracts are copied a second time after the old server is stopped, which catches a write already in flight. If that second copy fails the previous build is started again. No route is added; the check runs after the central guard.
- fix: `newestReleaseId` (and so the badge and the `RELEASE` consistency check) ignores junk ids: only `R<digits>` and `R<digits>.<digits>` count, so `## __proto__`, `constructor`, `beta` or an unsafe-size number can never be the newest release; a minor counts only under its own release; the result is the canonical id.
- fix: Waiting versus Gap no longer depends on the words of a cell. The pipeline's tree (`src/tree/model.mjs`) flags a red cell whose Ask is open with `waiting: true` and the demo reads the flag; rewording a hint or a cell cannot flip a Gap into Waiting (tested against all 12 examples). No wording or generated file changes.
- fix: **Wire it** and the Suggest switch stay pinned to the bottom edge of the first screen, so the button is reachable without scrolling at 1280 by 900 in Presenter mode too (it sat at 1075 px), with 13 endpoints in the Contract card, and on a short window.
- note: tests added for each of the above (atomic carry with injected failures, the lock and the re-carry with fakes and scratch dirs, a real server behind a scratch `deploy/<version>`, junk changelog ids, the first redeploy over a build whose manifest lists no contracts, nested paths on an example, and Waiting versus Gap on every example).

## R0 — 2026-09-27

- note: R0 is the first release. It merges the hardened server, the theme, the email composer and the deploy tooling with six pieces of work: the eval harness, the API contract as an OpenAPI file, real Subframe TSX pages, the Trace demo front door (with a canvas trace and a 3D hero), and the Part inspector. Details below, newest change first within each kind.
- feat: Trace demo front door at `/`: pick one of three curated screens (Portfolio Health, Invoices, Orders), press Wire it, watch the designed page fill with Fit / Gap / Tie / Stub, answer the Asks with a click (or let Suggest answer what it can), then read the four Handoffs (Backend, Product, Design, Frontend) with their emails. It speaks only the small pattern vocabulary in `src/ui/vocab.mjs`. `npm run demo` runs a preflight (`npm run demo:check`) and starts the server; a busy port 4177 is a warning, not a failure.
- change: the full studio moved from `/` to `/studio` (Details in the demo opens it, Back to Trace returns); the About page's back link, the tests and the deploy health checks (`/api/health`, `/api/build`, which do not depend on either page) are updated.
- feat: the fit screen draws each part's trace back to the contract on a 2D canvas: a pulse per part, a Contract rail with one chip per endpoint, a Map view (drag, zoom, click a part), Replay the trace (`T`), the same facts as a text list, and reduced-motion support. It only draws what is on the page and never changes a result.
- feat: a small 3D version of the Trace mark on the first screen (Three.js bundled locally with esbuild, lazy, with a static-mark fallback for no WebGL, reduced motion, Data Saver, low battery and narrow windows; `/?hero=off` turns it off; `npm run build:hero` rebuilds it).
- feat: the demo's Contract card takes an uploaded Swagger/OpenAPI file (file picker or drop), checked by the same code as the studio's upload; Reset demo restores the original contracts. "Backend ships the fix" saves `fixed.openapi.json` as the Orders contract.
- feat: the API is a Swagger/OpenAPI file in the feature's own folder (`openapi.json`, `.yaml` or `.yml`, Swagger 2.0 or OpenAPI 3.x); `feature.json` no longer lists `apis`. One loader (`src/contract.mjs`) serves the pipeline, the CLI, the server, watch, reset, the bench and the eval. Read deterministically by `src/openapi.mjs` (local `$ref`s, `allOf`, `{id}` to `:id`, base paths, examples from `example`/`examples`/`default`/a single `enum`, envelope lists found from the contract). Adds the `yaml` dependency.
- feat: upload a contract in the studio (file picker and drop zone in the API contract section) or with `POST /api/openapi?example=<name>` (JSON `{ name, text }`); it is validated and saved as the folder's only openapi file, and a bad file is refused with the reason. The route sits behind the central guard like every other.
- feat: a run without a contract is allowed and honest: one notice at the top of the run, `REPORT.md`, `REPORT.html`, `status.json` and the summary; every part that needs the API says the contract is missing; nothing is asked (or answered by AI) until there is something to match; the generated code is stubs. A missing example is a named gap, never a guess. Try `examples/products-no-contract`.
- change: the 11 shipped examples were migrated with `scripts/apis-to-openapi.mjs`; their generated code is byte-identical to before (a golden test checks every file); only the hint text of `deals` and `orders` changed, because it pointed at `apis` in `feature.json`. The Orders fix is `fixed.openapi.json`.
- feat: Part inspector: after a run, every part that needs a human has a badge (Gap, Tie, Stub, No endpoint) on the page, on the "Needs a human" list and on the Handoff items, in the demo and (double-click or Inspect) in the studio. Click one to see its options with proof on the design's own examples, the API source, the code generated today, and the effect a change would have (`13 of 19` becomes `14 of 19`, the files that would change) before anything is written.
- feat: Apply, Undo and Redo per part or for the whole example, recorded in `answers.history.jsonl` (kept across redeploys, cleared by Reset); Fix all similar applies one choice to the parts with the same kind of problem and the same candidates; a Stub can be written as an expression, run by the restricted evaluator on the design's examples (`src/ai/safe-eval.mjs`, never as JavaScript).
- feat: Suggest for one part (`POST /api/suggest`): one small, checked AI call that can only pick one of the rule-computed options and must cite a fact; it writes nothing, applying stays a click. A scoped chat (`POST /api/part-chat`, task `part-chat`) answers only about the part on screen, refuses anything else, and its reply is fact-checked; it can propose an option number but never apply one.
- change: the first option in the inspector is tagged Rule default (it was called Recommended): it is only the first option in the rules' fixed order (cheapest first, then alphabetical), not evidence that it is right.
- feat: real Subframe TSX pages: `extract()` reads TypeScript, member tags (`Table.Row`), fragments and `{"text"}` children (the 11 examples extract byte-identically); `src/import/` suggests where `data-dyn` / `data-list` / `data-action` belong on an unmarked page (yes/no questions, strong or weak with a risk) and writes the accepted ones as exact text splices; the pipeline formats a `.ts/.tsx` page with prettier `babel-ts`.
- feat: `src/construct.mjs`, the one seam to Construct: with `CONSTRUCT_ROOT` set, `packages/ast` is loaded at run time; unset or failing, Trace's own Babel fallback gives the same results (asserted in tests). No new runtime dependency; see `docs/CONSTRUCT-REUSE.md`.
- feat: eval harness (`npm run eval`, `eval:gate`, `eval:baseline`, `eval:triage`, `eval:promote`, `eval:labels`, `eval:worksheet`): scores Trace against ground truth (the 11 examples plus a seeded synthetic corpus of adversarial cases), records today's algorithm as `eval/baseline.json`, and gates changes on determinism, wrong-accepts, recall and oracle accuracy; see `docs/EVAL.md`. Its ground truth is labelled by source (`independent`, synthetic `reference`, Trace's own `self`) and the gate is a regression detector, not an accuracy measurement.
- feat: blind labelling worksheets for the 11 examples (`eval/labeling`) and a loader that folds filled ones back in as independent labels.
- change: the eval reads a case's contract with Trace's own `src/contract.mjs` (one OpenAPI reader, not two); the baseline was regenerated once because the endpoint-order check now also flags `decoy-endpoint-01`, a documented case of the same weakness. The headline numbers did not move.
- change: the redeploy keeps the running app's state (`answers.json`, `answers.history.jsonl`, `decisions.json`, `ai-cache.json`) but an example's shipped `openapi.*` is source: editing it in the tree makes a new build. The running copy is only kept when it was changed or uploaded in the app (it no longer matches that build's own manifest).
- fix: a missing report (`/report/<name>` before any run) is a 404, not an empty 200 with a headers-already-sent error in the log.
- change: every route the merged server exposes sits behind the central guard: `/api/openapi`, `/api/suggest`, `/api/part-*`, `/api/demo/*` and the static pages are dispatched after `checkRequest`, read bodies only through the bounded JSON reader (a bad body is 400, an oversized one 413), and take only a model name from a client. `src/server.test.mjs` asserts a foreign Origin/Host and a `text/plain` body are refused on every route, and that the hostile-expression suite is refused by the inspector's Stub route.
- change: the debug hooks `window.__trace` and `__traceHero` exist only with `?canvasdebug` on a dev checkout, never on a deployed build.
- note: Trace is the product name in every page title and brand (studio: `Trace · Studio`); "Seam" remains only as a glossary term in the demo's vocabulary.
- note: hardening is the release gate for R0: the server no longer trusts what a request says.
- fix: bad JSON in a request body no longer kills the server: it answers 400 with a JSON error. A body over 2 MB gets 413, an aborted upload is survived, and an exception in any route returns 500 without exiting.
- fix: no route can be driven from another web page. `src/http-guard.mjs` is the one place that checks every request: `Host` must be localhost / 127.0.0.1 / [::1] with the server's port (403 otherwise, also defeats DNS rebinding), a state-changing request must carry `Origin: http://<that host>` if it has an Origin (403) and `content-type: application/json` (415), so a cross-site `text/plain` or form POST is refused. New routes must go through it.
- fix: a request can no longer choose where a model call goes. In `ai.tasks` only a `model` name is taken (a model for Anthropic, or a remote OpenAI-compatible server, must be one the server config names or lists under `allowedModels` in `ai.config.json`); `provider`, `baseUrl`, headers and keys come only from the server's own files. Base URLs must be http(s); the Anthropic key is only ever sent to `https://api.anthropic.com`, an OpenAI-compatible key only to a loopback server or a host listed under `keyHosts`; redirects are not followed. The CLI (`--ai-task`) and the bench are trusted callers and still set the provider.
- change: the Options menu shows the provider of each AI task but no longer edits it (edit `ai.config.json`); the model name still can be edited.
- fix: the expression a model drafts for a placeholder is no longer run in a `vm` sandbox behind a regex deny-list (`item["constr"+"uctor"]["constr"+"uctor"]("return process")()` reached the host `process`). `src/ai/safe-eval.mjs` parses it and interprets an allow-list (own-property reads, a fixed list of pure methods, arithmetic, templates, `map`/`filter` with arrow functions it runs itself); everything else throws `expression not allowed`. Limits: 200 characters, 10,000 steps.
- fix: `/api/watch` refuses an example name that does not exist.
- fix: the top bar stays on one row at 1280, 1440 and 1920 px, light and dark, also after a run (it wrapped to two rows and covered the page). The example picker and the status text shrink first; the build badge is short from 1500 px and long from 1700 px.
- fix: the page title and brand say "Trace" (they said "line-matcher").
- fix: a redeploy keeps `answers.history.jsonl` like the other state files (a contract uploaded in the running app is kept too, but a shipped `openapi.*` is source: see the redeploy item above).
- fix: `.gitignore` ignores only the root `/deploy/`, not the source folder `src/deploy/`.
- fix: `demo-app/src/features/portfolio-figma-1/page/PortfolioFigma1Page.jsx` is generator output again (it had lost its trailing newline).
- note: tests for all of the above: `src/server.test.mjs` (real server on a loopback port with a fake model), `src/http-guard.test.mjs`, `src/ai/config.test.mjs`, `src/ai/safe-eval.test.mjs` (including a seeded fuzz), `src/question-context.test.mjs`.

- note: new `docs/SECURITY.md` (also linked from the About page): the guard rules of `src/http-guard.mjs`, the rule that every new route goes through `checkRequest`, what a request may choose for an AI call (a model name only), and the `allowedModels` and `keyHosts` settings of `ai.config.json` with defaults and examples. - note: a rollback carries uploaded contracts only; saved answers and other run state are still seeded at deploy time from the previous build, so answers given after the build you roll back to are not carried by a rollback (unchanged behaviour).
