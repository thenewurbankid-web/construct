# Page map (v1)

A page at `/pagemap` that reads a designed page (JSX or TSX), lists **every element and text node**, proposes for each one **what it is** (dynamic value, static copy, list row template, action, input, visual, or unsure) with a **strength, the reasons and the false-positive risk**, collapses repeated rows and cards into one template with a count, and lets a person **accept, reject, change or add** each proposal on screen. Nothing is written to the design; decisions live in a sidecar and can be turned into a **marked copy** of the page (`data-dyn` / `data-list` / `data-action`) that the extractor reads.

Open it with `/pagemap?example=<name>` (an example's `page.jsx`, its existing markers show as *accepted*) or `/pagemap?file=<page>.tsx` for one of the three real Subframe pages (`PortfolioHealthFigmaRebuild.tsx`, `PortfolioHealthFigmaRebuild2.tsx`, `RedesignedPortfolioHealth.tsx`; each is read against the contract of the example that holds the same design: figma-1, figma-2, redesigned).

Why not Craft.js (research, 2026-09-27): it has no JSX round trip, needs the page rewritten as its own component tree (that breaks Trace's frozen-markup rule) and needs React everywhere. The page map is a small overlay in plain JS on Trace's own parser.

## The model (read the user rules below too)

- **Inventory** (`src/pagemap/inventory.mjs`, pure): the full node tree. Every element and every text node (JSX text, `{"..."}`, template literals without expressions, `{expression}`), plus the attribute text a person or a screen reader meets (`alt`, `aria-label`, `title`, `placeholder`, and the visible props `label`, `helpText`), flagged `a11y` where it applies. Each node has a **stable id** (`n` + hash of file name, line:col and tag path; never random), a **kind** (`text | interaction | input | list | table | row | cell | media | visual | container`) and details: text (literal or expression, example value), interactions (tag, label, handler props such as `onClick` / `onSubmit` / `href` / `type=submit`, the verb from the label), inputs (type, name, label, placeholder, options, required, disabled, default), tables and lists (template row, columns with header text and example cells, row count, rows), media and visuals (element, alt, aria text). Elements inside a prop (`mainMenu={<>...</>}`) or a `{...}` expression keep that as their slot; a `.map()` row is a group of one with an unknown count.
- **Collapse** (`src/pagemap/collapse.mjs`, pure): 3+ adjacent siblings with the same structure hash (text between two siblings ends a run), **all data rows of a table** (their shapes differ in badges and cells) and `.map()` rows become one group: the first instance is the template, the rest are its instances, and every slot (text, attribute text, prop) lists the values that vary. The same component or card in several places is marked **repeated component xN** with what varies; it is not merged. It is **reversible**: `visibleIds(inv, cx, "all")` is every node once; nothing is deleted.
- **Classification** (`src/pagemap/classify.mjs`, pure): one proposal per node. The import block's suggestMarkers rules run through `planMarkers` (numbers, money, dates, percents, deltas, "N of M", repeated rows, verbs on buttons, form inputs: ONE implementation, not a copy) plus: a text equal to an API example value of the contract is a strong hint (`contract-match.mjs`, the closed formatter and aggregate library; a bare 1-2 digit number or an aggregate only weak); a sentence that names an API value is **unsure**; a number inside a sentence that equals an API value becomes a strong token-level proposal (only the number is wrapped); a table header text maps to its column; text in a **strong list's row template is dynamic unless identical in every row**; a stat card's label (label + big number) is static; text inside a control is its label; attribute text is static; an existing marker is **accepted**. A decision on a template row covers its instances (`follow`), but only for a strong list: the items of a stat strip, a chip row or a legend are decided one by one.
- **Coverage**: every node is in exactly one bucket, so the buckets add up: `N nodes: X dynamic, Y static copy, Z actions, W inputs, L list parts, V visuals, S structure, K unsure`, and "100% accounted for" is checked by a test.
- **Issue kinds**: `unclassified` ("Unclassified text": no rule fired and there is no contract to compare with) and `ambiguous` ("Ambiguous: dynamic or copy?") were added to the inspector's registry (`src/ui/issues.mjs`), and the page's Fix area reads the registry (badge, explanation, form title) like the inspector does.

- **States and conditionals** (`src/pagemap/states.mjs`, pure): what the design shows only sometimes is listed as **state records** (`kind: "state"`, own stable id `s...`, `target` = the element it affects, the condition text, `branch` then/else, a proposed **requirement item** for Product or Design). Sources: conditional rendering (`cond && <X/>`, ternaries with the else branch as `not (cond)`, a `.map()` with an empty branch), state props (`disabled`, `aria-disabled|selected|expanded|busy|checked|pressed|invalid|current`, `selected`, `active`, `loading`, `checked`, `expanded`, `variant="selected|active|..."`), state class tokens, skeleton / `animate-pulse` elements, and loading / empty / error wording. Records are not tree nodes, so the tree's 100% coverage and all node ids are untouched. A condition names its kind (empty, loading, error, selected, disabled, else conditional). A colour variant (`Badge variant="error"`) is a style, not a state. In the page: **States & flows** tab, keep as a requirement or dismiss (a decision, undoable). Not built yet: inferring the requirement from the condition's variables, and linking a state to the API field that drives it.
- **Interactions and their resolution** (`src/pagemap/interactions.mjs`): the flow rule is that every interaction resolves to an **API endpoint**, a **controller function** or a **marked stub**; a stub is any function with an unused input or nothing returned (`onClick={(event) => {}}`). Each interaction is listed with `api` (a known verb and the contract has the endpoints), `controller` (a UI-only verb such as select or cancel), `stub` (no home yet and the handler is a stub) or `unresolved` (unknown verb, no handler, or an endpoint the contract lacks). The verb's kind is the pipeline's (`match.mjs` `matchAction`), with or without a contract: edit/open/select and cancel/close/reset are UI-only (`controller`); a verb that needs endpoints resolves to `api` only when the contract has them, and without a contract it stays `unresolved` (nothing is claimed). A test compares this with the pipeline's own action kinds on all 12 examples. No model.
- **Charts** are summarised by mapping: the labels inside a graphic (series, axis, legend text, alt/aria/title) are listed with the data items of the contract they could stand for (`contract-match.mjs` `dataItemsFor`: a value it equals, or a field whose name has its words). Candidates only; the user confirms.

## User rules (decided in the tracker), and how they are honoured

1. **Two identical texts in different places are two parts.** Node ids contain the position (file, line:col, tag path); nothing merges by text. A test pins it. (Repeated rows collapse only by structure and only in the *view*; each instance keeps its own id.)
2. **Text that is neither marked nor static is static at least.** An unsure node counts as static until decided (the coverage sentence says so, `coverage.staticAtLeast`), and nothing is ever written for it; a no-rule text is weak static.
3. **Suggested markers are suggested by Trace, confirmed by the user, and stored as violations.** `src/pagemap/violations.mjs` builds a tracked list, one per open question: `{id, rule, severity, file, line, message, why, expected, suggestedFix, nodeId, status, team}`. `status` may also be `orphan` (see above). The first seven fields are Construct's `makeViolation` shape (Construct also requires a `module` from three closed values, so Trace builds the object itself; a test validates every violation against Construct's function with `module: "readability"`). Rules: `pagemap/dynamic-value|list|action|input`, `pagemap/unsure`, `pagemap/state/<kind>`, `pagemap/interaction-unresolved|interaction-stub`, `pagemap/chart-mapping`. `status` is `suggested`, `confirmed` (accepted or changed) or `dismissed` (rejected) and follows the decisions. The list is in the page's summary line and in the **States & flows** tab, and is stored in the sidecar (`pagemap.json`, key `violations`) after every decide / undo / redo, so a run summary or a team email can read it later (not wired yet).
4. **Columns and table content are tracked by index/position:** a table's columns are `{index, header, examples}`, a row has `details.index`, a cell `details.row` / `details.col` (shown in the panel).
5. **Charts are summarised by mapping** (see above).
6. **Flow definitions:** every interaction resolves to an API endpoint, a controller function or a marked stub; the map lists each with its status (see above).

## Node ids are POSITIONAL (read this before editing a page)

A node's id is a hash of the file name, the line and column, and the tag path. So **any edit that moves a line, even a whitespace-only one, changes ids and orphans the decisions made on them.** Orphans are never guessed at or silently re-mapped: the summary line shows `N orphaned decisions`, the **States & flows** tab lists each one with the line and text it was made on, and you either **re-attach** it (select the node that is there now and decide again) or **drop** it. The same text in two places is two parts for the same reason. The page's "How ids and decisions work" box says this too. **The re-anchoring rule.** A decision stores an anchor (line, column, tag path, text and a *signature* of the node's kind, tag, path, text and structure). It is **live only if its id exists AND the signature of the node now at that id equals the stored one**; otherwise it is an orphan. So a decision can only ever apply to the node it was made on or to an *identical* one (same text, tag path and structure, e.g. two identical rows: the decision then describes the node at that position, which is the same thing). When identical-shaped rows shift (delete the first row and the second lands on the first's position), the id collides but the signature differs, so the decision is an orphan and apply/use cannot mark the wrong row. Nothing is ever re-anchored silently: the user re-attaches or drops. Tests pin all three cases (a different node at the same id, nothing at the id, an identical node at the id). An edit whose target is no longer on the page is recorded as an `orphan` (a note on the edit, status `orphan` in the violation list), skipped, and never throws; a failing side section (violations, diffs, interactions, chart mapping) degrades to an entry in the payload's `warnings` instead of taking the page down.

The sidecar is read defensively: invalid JSON, a file over 2 MB, a non-object root, and entries that are not objects, have an unknown act/class, an unusable name, a non-object anchor or a key that is not a node id are dropped, each reported as an entry in the payload's `warnings` (shown in a banner on the page). A damaged sidecar is never a 500.

## Decisions, the marked copy, and what is written

| File | Where | What |
|---|---|---|
| `pagemap.json` (real page: `pagemap.<Page>.json`) | the example's folder | current decisions, sorted keys, versioned; provenance `by: "rule"` (the user accepted what a rule proposed) or `"user"` (chose, added, renamed, rejected) |
| `pagemap.history.jsonl` (`pagemap.<Page>.history.jsonl`) | same | append-only, one line per change, group per bulk; Undo/Redo like `answers.history.jsonl` (reuses its `stable` and `fold`); a change made by hand in the sidecar is never overwritten, Undo says so |
| `page.marked.jsx` (`<Page>.marked.tsx`) | next to the example's page (a real page: the example's folder, **never** `subframe-app/`) | `Apply to a marked copy`: exact-offset splices, idempotent, byte-deterministic; only ACCEPTED decisions write; the diff is shown |
| `page.before-pagemap.jsx` (then `.before-pagemap.2.jsx`, `.3`, ...) + the page itself | example's folder | only on the **second, explicit step** `Use as the page` (needs `confirm: true`, an example page, and a marked copy that equals what the current decisions produce; a real Subframe page is never replaced); decisions start over because lines move. **A backup is never overwritten** (claimed with an exclusive create, `wx`: it fails on any existing entry, a dangling symlink included, and never writes through a symlink; on `EEXIST` the next number is tried, 50 at most, then a clear 409 and the page is not replaced; two requests picking the same name cannot both get it). A second `use` when the page already is the marked copy answers `unchanged: true` and writes no backup: the first original stays `page.before-pagemap.jsx` forever, and each later use keeps the page it replaces under the next free number. **Undo path:** copy the backup you want over the page (`cp page.before-pagemap.jsx page.jsx` restores the very first original). |

The design source is never modified except by that second step. For the edits the import block's rules would make, the bytes equal `applyMarkers` (a test pins it; `attrInsertion` is imported from `src/import/apply-markers.mjs`, where the only change is the added `export`; `apply.mjs` passes it an element shim built from the node's `spans`). A data-dyn on an element that holds another marked value is written as a `<span>` around its own text instead, so two markers never nest.

## Routes (`src/pagemap-routes.mjs`, one line of wiring in `src/server.mjs`)

`GET /pagemap`, `GET /pagemap/pagemap.mjs|css` (allow-list), `GET /api/pagemap/pages`, `GET /api/pagemap?example=|file=`, `POST /api/pagemap/decide | undo | redo | apply | use`. All pass `src/http-guard.mjs` first (Host, Origin, JSON content type), read bodies only through its reader (bad JSON 400, over 2 MB 413), take `example` from the known examples and `file` from the fixed list of real pages (no path can be named), validate node ids, classes (`dynamic static list action input visual`) and names (`[A-Za-z][A-Za-z0-9_]{0,39}`), and write only the fixed file names above. `src/server.test.mjs` lists all of them (foreign Origin/Host, text/plain and form posts, bad JSON, unknown example); `src/pagemap-routes.test.mjs` runs the flow on the real server (path traversal, the two-step write, only-these-files-appear). No model is ever called.

## The page

Left: **States & flows** (requirement items, interaction resolution, chart mapping, tracked violations), **Structure** (collapsed tree, expand/collapse, filters by class/strength/needs-review/unsure/icons, search) and **Review all proposals** (strong first, Accept / Reject per row). Middle: a **wireframe** drawn from the same tree (a `data-pm-id` on every box, coloured by effective class; click selects, hover on a tree row highlights), the **source** (selected node's lines highlighted) and, for JSX examples, the **original preview** (`/api/preview`, unchanged). Right: the node panel: class chips (**Mark this as**: any node, including one nobody suggested), Accept / Reject / Clear, the name written (editable), the Fix area for unsure and unclassified nodes, the reasons and risk, what repeats and what varies, and **the proposed edit as a diff of the source**. Top: the coverage bar, "X proposed edits: Accept all strong / Review weak", Undo / Redo, Apply to a marked copy. One shared handler (`dispatch` in `src/ui/pagemap.mjs`) takes every click, change and key by event delegation, keyed by `data-act` and by node id; the tree is a `role=tree` with arrow keys, Home/End, Enter; both themes come from `/theme.css` tokens. Screenshots: `docs/pagemap/` (regenerate, and check for console errors, with `node scripts/pagemap-shots.mjs`; it needs Chrome and starts Trace on port 4300 with a scratch copy of the examples).

## Measured (`node eval/pagemap.mjs`, `eval/pagemap.test.mjs` pins it)

Against the hand-marked example pages (same designs as the three Subframe pages), compared by text; the old rules' numbers are recomputed and equal the extraction slice's recorded baseline (parts extracted / matched to exactly one API source, on the auto-marked page: 16/4, 15/5, 13/4; hand-marked: 36/15, 36/15, 25/7).

| | figma-1 | figma-2 | redesigned |
|---|---:|---:|---:|
| strong dynamic proposals: precision / recall (page map) | 92% / 83% | 94% / 84% | 87% / 88% |
| the same, import rules alone | 96% / 54% | 100% / 55% | 95% / 59% |
| strong + weak: precision / recall (page map) | 86% / 91% | 90% / 93% | 83% / 92% |
| parts extracted / matched after accepting strong (page map) | 25/10 | 24/11 | 19/7 |
| the same, import rules alone | 16/4 | 15/5 | 13/4 |

It beats the earlier baseline, more coverage for a few points of precision, and it does not reach the hand-marked pages (36/15, 36/15, 25/7): what is left is numbers inside sentences (weak), narrative text that names no API value (its text is only `unsure` when it names one), and values the contract does not carry. Action recall is bounded by design differences (the hand pages add an "Open" button per row that the Subframe pages lack). `npm run eval` and its gate are untouched (this is a separate section, so the baseline hash does not move).

## Reuse of Construct (through `src/construct.mjs` only)

- Reused: `packages/ast` through the import block (`parseJsx`, `walkAst`, `spliceNode`, `renderAttrValue`; with `CONSTRUCT_ROOT` unset the Babel fallback runs and gives the same results). New in the adapter: `importConstructModule(root, rel, names)` and `importConstructAnnotator()` (null when unset, missing or broken). `jsxSourceAnnotator` is used in a test: its `data-cx-src="file:line:col"` equals the page map's node position for every host element of two real pages (skipped without a checkout), so a click on a *rendered* host element can select a node without guessing.
- Not reused, with reasons: `core/text-diff.mjs` `buildDiffView` (needs the `diff` package, which resolves only from the checkout's own `node_modules`; Trace already has a tested dependency-free `src/diff.mjs`); `engine/transactionalWriter` (the writes are three fixed files, each an atomic temp-file rename; no multi-file transaction is needed); `core/llm` (no model is called); `engine/previewFiber` `resolveFiberSelection` and `previewBridge` (they need a running rendered app with the dev-only annotator plugin; v1 draws its own wireframe with an id per node, so a click maps by construction); `core/validate` enforcers, `workflow*`, `pageTransformer`, `controllerBinder` (a different job).

## Gaps for the Construct owners

0. `makeViolation` accepts only three `module` values (`architecture`, `separation-of-concerns`, `readability`), so a tool other than the enforcers cannot use it as it stands; a free `module` (or none) would let Trace call it.
1. `jsxSourceAnnotator` annotates host elements only ("custom components and fragments are left alone"), and a Subframe page is mostly components, so a click on the rendered page lands on a host element inside a component; the page-level call site is found by walking up to the nearest annotated ancestor, which needs the page's own file in the map. An option that annotates custom components with a *wrapper-free* attribute (or a `key`-like prop the design system forwards) would remove the walk.
2. `buildDiffView` needs `diff` from the checkout's own `node_modules`; an import from outside the checkout fails, so a consumer can only use it when it also owns that dependency.
3. (repeated from `CONSTRUCT-REUSE.md`) no batch/multi-edit primitive for `spliceNode`, and `setAttributeText` does not follow the tag's layout, so Trace keeps its own layout-aware `attrInsertion` (shared by the import block and the page map).

## Known limits, next steps

- The click-to-source overlay on the *rendered* Subframe app is not built (stretch item; the positions agree, see above). The wireframe is not the design: components are boxes and only flex/grid direction is read from Tailwind classes.
- Naming reuses the import block's rule (nearest label, first words), so names such as `yourPortfolioAtA` are poor; they are editable and an accepted name is what gets written.
- A page edited elsewhere moves the ids (they contain the position); the page reports how many saved decisions no longer match instead of guessing.
- Suggested capability row for Construct's `docs/capabilities.md` (do not commit there from this branch): **Page map** (node inventory, repetition collapse, classification with reasons, decisions with history, marked copy) | `line-matcher/src/pagemap/` (entries `inventory.mjs`, `collapse.mjs`, `classify.mjs`, `apply.mjs`, `service.mjs`) | the Trace `/pagemap` page | Det | Packaged (JSDoc, node:test fixtures on three real Subframe pages, a measured eval).
