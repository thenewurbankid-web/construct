# Line roadmap (owner, 2026-10-12): primitives, Line-1, tests first, model roles

This replaces the earlier partial pastes. Item 1 and item 2 (core) are pulled into the enterprise MVP; see `project-scope-freeze` in memory and the tracker's "Enterprise MVP" stream.

**Next sprint:** 1, 2, 7, 8, 9, 10. **Later:** 3, 4, 5, 6, 11–18.
Line-1 detail lives in `LINE-MODEL-ROADMAP.md`; middleware detail lives in `MIDDLEWARE-ROADMAP.md`.

1. **Canonical primitive library.**
   - Learn structure from permissive UI libraries: Radix, React Aria, Headless UI, Ark, shadcn/ui, Mantine, Chakra, MUI.
   - Cluster their components with Trace-style descriptors.
   - Re-implement one canonical Line primitive per cluster on Radix + Tailwind. Never copy code.
   - Each primitive carries the full set of states, events and accessibility seen across the sources, plus a test kit.
   - Start with a core of 30–40 primitives and grow from measured misses.
   - Per-release metric: % of held-out library components that map onto Line primitives with no loss.
2. **Logic atoms.**
   - Extend Smith/atomic-codemod with functional primitives from react-hook-form, zod/valibot, TanStack Query/Table, xstate/zustand, react-router and date-fns.
   - Examples: validated submit, paginated query, optimistic update, multi-step flow, filter/sort, permission check.
   - Domain logic is mostly compositions of atoms. Each atom ships a test kit.
3. **Three tiers for all code.**
   - **T1, new code:** written as atoms and primitive-based parts. Promote it to the project library, then contribute it upstream in the next version.
   - **T2, code that can't be converted:** a first-class case (about 10% of UI is genuinely unique). Wrap it as a Line resource behind a middleware/adapter:
     - a contract descriptor;
     - Line rules enforced at the boundary, with boundary characterization tests;
     - the refusal offers "Wrap as a Line resource" or "Keep outside Line";
     - it can be broken into atoms later, behind the stable adapter.
   - **T3, repeated project patterns:** named patterns with fixtures, reused through memory/recall, contributable upstream.
4. **Line-1, our own small model (open source).** See `LINE-MODEL-ROADMAP.md`.
   - CPU-only path.
   - An "AI off" mode with full static functionality.
   - A per-version accuracy card.
   - Order: Route first, then Pick and Repair. Code fill stays with the small Qwen coder, behind tests.
5. **Tests drive development.**
   - Every generated piece writes its tests into the project. The tests are the user's and editable; Line never overwrites a test a person edited, and only proposes changes as plan steps.
   - Order: spec points → expressions → tests (failing first) → code. A step lands only when its tests pass.
   - Trivial edits (text, props) re-run the existing tests.
6. **No-code, deterministic tests.**
   - Tests are data:
     - given: fixture + start state;
     - when: actions from the item's real events;
     - then: Line expressions from a closed list (text, state, validation, navigation, service-call shape, screenshot).
   - Construct renders tests deterministically.
   - The Cockpit Tests tab asks one question at a time. Every edit is a plan step, and fixtures use closed forms.
   - No AI in creating, editing, rendering or running tests. AI only suggests; a person approves.
   - Code edits read back into specs when they fit; otherwise the test is marked "custom (code only)".
7. **Visual results and findings.**
   - Screenshots per UI test: a state strip per item, and a before/after in each plan step.
   - Keep the latest set plus approved baselines.
   - New findings, each with typed fixes, shown in Cockpit, "How smart is it" and Trace highlighting:
     - missing states;
     - missing validations;
     - broken links, routes and imports (G1);
     - untested or unreached logic (G2 + coverage);
     - visual regressions.
8. **Theming and design tokens.**
   - Tokens, variants, dark mode and brand presets over the primitives.
   - A path from Figma/Subframe designs onto primitives + tokens (Trace, GateLM recognise).
9. **Upgrade path across Line versions.**
   - Version pinning, deprecation notices, codemods as plan steps.
   - An upgrade preview, with tests proving nothing broke.
10. **Backend and data primitives.** API contracts (OpenAPI via G3), auth and permissions, data schema, persistence: atoms and primitives like the UI ones.
11. **Eject.** Generated code stays plain React/TypeScript, with a documented "leave Line" path.
12. **Collaboration.**
    - Branches and PRs, and plan-step review by others.
    - Conflicts between plan steps and hand edits.
    - Several people or agents per project.
13. **Security.**
    - Dependency and licence audit, and secret scanning.
    - Unsafe-pattern findings (XSS, raw HTML, open redirects).
    - Sandboxing for anything a model or a test runs.
14. **Accessibility, i18n and performance findings with typed fixes.** Contrast, labels, focus, untranslated strings, bundle and render budgets.
15. **Onboarding.** A working, tested feature within minutes, with guided tours on the two-mode screens.

16. **Model tiers.** The AI role grows with the model and is set per step in the AI profiles.
    - **Pick** (1.5B, Line-1): choose among options that are already verified.
    - **Propose** (Haiku-class): add routes, fixes and arguments. Construct verifies each one in a scratch copy first.
    - **Author** (Opus-class): build what's missing. That means a fix where no typed fix exists, a missing tool step made from existing tools plus checked code, or new primitives and atoms.
    - **Static is the floor, not the ceiling.** Every gap that gets bridged is captured as a miss plus the solution that worked. The rule factory (cs2) turns repeats into typed fixes and tools for the next Line version.
    - **Guardrails stay.** Construct decides what lands, and a person approves writes. Every proposal is labelled with its tier in the decision trace. Line works fully offline, with no hosted model.
17. **Model switching.** Settings → AI steps lets you pick a model per step: Off/static, Line-1, local 1.5B, Haiku, Sonnet or Opus. There are three presets:
    - **Local only:** private, free, offline.
    - **Balanced:** Haiku for propose and repair, local for the rest.
    - **Max:** Opus for author, routing and fill.

    Each choice shows its tier, its cost per step (from the token log) and a privacy note ("sends code to Anthropic").
18. **Internal model and external agent as complementary reasoners.**
    - **Internal** (Line-1, small or static) reasons about HOW, within Line: closed, structural and rule-exact.
    - **External agent** (Opus or Sonnet through MCP, Auto or plan-cli, or a person) reasons about WHAT and WHY.
    - **Flow:**
      1. The agent states the intent.
      2. The internal model proposes verified Line options.
      3. The agent reviews them and picks one, or explains why none fit.
      4. On a disagreement, both reasons are kept and Construct verifies the alternative. Then the agent accepts with a reason, or the person decides.
    - Every disagreement is recorded as training signal for cs2 and Line-1.
    - The internal model stays small. An Opus internal model is used only at the author tier, and the agent still reviews it.
    - This extends LINE.md's "Qwen suggests, jev decides, Qwen reviews" pattern and am1 ("weak decisions go to whoever drives").

**Benchmark (extend bench/ecommerce).**
- Arms:
  - agent alone;
  - agent + internal;
  - internal alone;
  - Opus driver + lean internal;
  - Opus + Opus;
  - local only.
- Measures: acceptance passed, refusals bridged, disagreements caught, tokens, and cost per passed test.

**Envelope reconciliation (backlog).**
- The problem: Construct's envelope (`schemas/envelope.v1.json`, `packages/engine/envelope.mjs` + `pipeline.mjs`) carries step-to-step state for the old `construct pipeline run`. Line uses the plan API, plan records and facts instead, so there are two models for one concern.
- Don't build the Envelopes composer (`docs/design/rules-envelopes.md`).
- Instead, a "flow" becomes a saved, reusable plan template whose steps are typed tool calls (T3 named patterns).
- Either run `construct pipeline run` through the plan API, or keep the envelope internal to the old generators until they're retired.
- Trace's "envelope" means an API list-response wrapper, which is unrelated.

**North star:** the share of each feature built from primitives, atoms and wrapped resources versus loose code, rising every Line version.

**Licence:** everything is open source for now, Line-1 included. The "Cockpit proprietary" note (board cu8, CLAUDE.md) is on hold; revisit it before any public release. max-ai-ui-derived content stays out of the public repo regardless.
