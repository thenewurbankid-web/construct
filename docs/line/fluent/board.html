When it's 100% done

Line reads any JavaScript or TypeScript and shows it as plain English sentences, with no AI model needed. Every sentence is checked to do exactly what the code does. You see it in your editor, from one command, in the Cockpit beside your code, and any AI agent can use it too. A small model on your own machine learns to write the same English.

How it's done

  1. Write the library. Claude writes one English sentence and one small building block for each of the 2,378 JavaScript features.
    How the algorithm works
    1. Take one entry from the JS reference: its name, sample code and signature.
    2. Look for an existing block that already does the job, so it can be reused.
    3. Send Claude a fixed request: the entry, the R1–R9 sentence rules and the nearest blocks.
    4. Claude answers in one fixed shape: the block, its sentence, the matching JS, and a decision (new block, existing block, a combination, or "can't be expressed, because…").
    5. Anything not in that shape is refused before any checking.
  2. Check every answer. Automatic checks test the grammar, run the code against real JavaScript and compare types. Anything that fails is refused.
    How the algorithm works
    1. Grammar: a closed word-by-word state machine checks the sentence follows R1–R9.
    2. Behaviour: run the answer's JS and the real JS on the saved expected results and on generated inputs; every output must match.
    3. Types: compare parameter count, order and kind with the reference entry. This check never compiles.
    4. The results combine into one verdict. A failure comes back as a plain-English refusal with a suggested fix.
    5. The answer gets one retry with that refusal. If it fails again, it is recorded as a known gap.
  3. Translate without AI. A fixed translator uses that checked library to turn your code into English.
    How the algorithm works
    1. Parse the code and match each call against the library's blocks.
    2. Swap each match for its block, then write the block's sentence.
    3. Run the converted code in a sandbox (QuickJS) and check it behaves exactly like the original.
    4. Anything with no match is marked "untranslated" or "refused", never guessed.
    5. The English is a read-only view. Your typed code stays the source.
  4. Teach the small model. It does the same job, the same checks grade it, and it trains on its mistakes.
    How the algorithm works
    1. The small model gets exactly the request Claude got.
    2. The comparison sorts each answer into one of three results: same as Claude's (a hit), equivalent (different wording, passes every check), or wrong (fails a check).
    3. Each wrong answer becomes a training record: its answer, the refusal and Claude's answer.
    4. Whole sections (for example Intl and Temporal) are held out, so the score shows real learning rather than memory.
    5. Train a small add-on (a LoRA) each round. If the held-out score doesn't rise, the loop stops and asks. The model only fills gaps until it beats the fixed translator.
  5. Put it where you work. The editor, the command line, the Cockpit and AI agents all use the same library.
    How the algorithm works
    1. Hover: find the block under the cursor and show its sentence.
    2. Completions: the grammar state machine lists the next legal words, so every suggestion is valid.
    3. Errors: the checks' refusals show as squiggles, each with a one-click fix.
    4. Go to definition: an index links each sentence to its block and the real JS.
    5. Command line, MCP tools and Cockpit call this same code, and the atom generator runs the step 1 pipeline on a single new API. Nothing joins the library until you approve it.
