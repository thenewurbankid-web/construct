Line · Smith · plan for the owner · 2026-10-15

JavaScript into fluent English, an LSP on top, and a small model that learns it

Claude writes the full fluent library from the JS reference under the latest Smith rules (R1–R9). That library is the base every app and model uses. The small model does the same work from the same JS, is compared with Claude's answers by checks rather than by opinion, and learns from the differences. Users get it through an LSP and generators, so they never write a sentence or a prompt by hand.

When it's 100% done

Line reads any JavaScript or TypeScript and shows it as plain English sentences, with no AI model needed. Every sentence is checked to do exactly what the code does. You see it in your editor, from one command, in the Cockpit beside your code, and any AI agent can use it too. A small model on your own machine learns to write the same English.

The stages

1

Claude writes the base fluent library Claude

For every JS reference entry, Claude writes the atom and its sentence under R1–R9, plus the JS twin. Each call has one fixed input and one constrained output, so nothing comes back as free text.

in:  { entry: "Array.prototype.flatMap", js: "xs.flatMap(f)", signature, rules: R1–R9, nearest atoms }
out: { atom: "flatMapped", kind: "copy", sentence: "every(x).in(xs).is().mapped().to(...).and().flattened()",
       js: "xs.flatMap(f)", decision: "new-atom" | "existing:<id>" | "molecule" | "not-expressible:<reason>" }
Status
Machinery done: answer shape (C2), the three checks (grammar, behaviour, types) and the combined verdict; the pilot's request builder, mock runner and Array entries. Writing the library (T1.4): not started. It waits on your go/no-go on cost.
Gate
The grammar test (R1–R9) passes. The atom matches its native JS under fast-check and matches expected.json. tsc and the type fixtures stay clean. An answer that fails gets the refusal sentence back once and tries again. If it fails again, it is recorded as a gap.
Order
One section first (for example, Array) to measure cost, pass rate and readability. Then es, then syntax, then web.
Owner
Approves new atoms only, in batches on the Smith Atoms page. A molecule that passes the six-check gate needs no approval.
Output
The catalog grows from 37 sentences toward full coverage. The gold set is (js, atom, sentence, decision) for every entry, and refusals are kept as data.
2

A static translator from JS to the English view static

The codemod's toAtoms writes the fluent form (build-order step 5) using only the catalog from stage 1. No model runs here. The English view is generated and read-only. The app keeps its typed code (decision 2, revised).

Status
Done: the fluent form (toFluent, fluentFor), the construct english CLI, and the coverage module (built, but not run: no benchmarks for now). writeAtoms writes the read-only English view next to the typed code (T2.4, merged with import v2). Not started: re-importing and measuring the corpus (no benchmarks for now).
Measure
On the whole JS reference: converts, refused, and untranslated, counted by kind. The same counts on real code: construct's packages, the bench apps, and max-ai-ui.
Gate
Converted code behaves the same (QuickJS, plus Node's expected answers). Every sentence passes the grammar test.
Output
line.import.writeAtoms writes fluent sentences (step 6), and the corpus is re-imported and measured (step 7).
3

The small model builds the same, and learns from the comparison qwen2.5-coder 1.5b

It gets the same input and the same output schema as Claude, one entry per request, with the signature prefilled. Its answer is compared with Claude's by checks, not by a judge model:

  • same: the same atom and the same sentence. That is a hit.
  • equivalent: a different sentence that passes every gate and behaves the same. The record is kept, and the owner can promote it.
  • wrong: fails a gate. The pair (its answer, the refusal, Claude's answer) becomes a training record.
Status
Done: the comparator (same / equivalent / wrong), the student request adapter, and the training-records writer with held-out sections. Held: the English-as-context probe (T3.4) and LoRA round 1 (T3.5). No benchmarks for now, and training waits for the probe.
Teach
A LoRA on the 1.5b (the native Line model goal), trained only on gated records: Claude's gold set, the student's corrected misses, the codemod's verified pairs, and translated permissive OSS.
Split
Hold out whole sections (for example, all of Intl and Temporal), so the score shows generalisation rather than memory.
Loop
Each round must raise the held-out score, or the loop stops and asks. The student runs in shadow until it beats the static translator on its own profile (ladder.measured). Until then it only fills the gaps static leaves.
4

Extend the Line LSP's Smith layer on top of the live index (#950). The grammar is a closed state machine, so most features need no model at all.

5

Generators and tooling, so users do almost nothing static

Status: construct english and the page rebuild script are done. The atom generator is merged; approved atoms live in line-smith's approved.json and survive catalog rebuilds. The Cockpit English panel (GET /api/line/english) and the MCP tools line_english and line_atoms are merged.

  • construct english <file>: prints the read-only English view of any JS or TS file.
  • construct atoms suggest: lists the functions that can become atoms or molecules, with the fix as a plan step.
  • A generator that turns a new JS API into a catalog entry and its sentence (stage 1's pipeline, run on one entry).
  • An editor extension and MCP tools (line_english, line_atoms) over the same LSP, so the user's own agent uses it with no prompt files.
  • A Cockpit panel showing the English view beside the code, with technical detail collapsed.
  • Rebuilt pages: the Smith Atoms page and the JS Reference Atlas, regenerated from the catalog after every batch.

StagePass bar
1 Fluent libEvery reference entry has a gated answer: an atom, an existing atom, a molecule, or a named refusal. Zero gate failures in the catalog.

3 StudentThe held-out "same or equivalent" rate rises every round, and K2 (0/20 today) is re-run on the trained model.
4 LSPDiagnostics exact on a fixed set (as smithDiagnostics was, 12/12). Completions are always legal sentences.
5 ToolingA new user gets the English view of a file in one command, and an agent gets it through MCP with no setup.

The probe still open from the carry-over decides whether the English view beats raw code as the small model's context. It runs after stage 2 and before any training spend in stage 3.
